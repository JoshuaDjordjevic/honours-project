- The model would hallucinate that it had tools if .bind_tools() was called with no tools provided; asking for the weather without a weather tool would trick the model into trying to call a tool, usually attempting to find one with the name 'weather_api' or similar, which would cause an error as the tool doesn't exist but a dictionary lookup would be attempted. This is quite interesting to see. Instead we only bind tools if using tools, and add a safeguard into the invoke method when checking model response for tool calls.
- The code had an error of originally only allowing the model to call a tool once. Now changed it so that the model can invoke a tool 4 times maximum per question.
- Question 12 tripped up the models. The baseline got the answer right - "What is the square root of 155875225?" -> "The square root of 155,875,225 is **12,485**.", but for some reason all other configs stated that the sqrt is 12483. They were accordingly graded low in terms of factual correctness and hallucination avoidance.
